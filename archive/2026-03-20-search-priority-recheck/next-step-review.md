# Search Priority Recheck

Date: 2026-03-20

Reason for this review:
- Re-audit the current progress and planning docs after the noir shell reskin.
- Re-decide the next highest-value step before opening any new system or content track.

## Current Read

- The vertical slice is now coherent enough that the main blocker is no longer "what is this game?".
- The biggest remaining friction is search-mode decision density:
  - what is safe right now
  - what is still exposed
  - what the next room would force back onto the felt
  - how visible the extraction choice is at common viewport heights
- Table depth and system depth still matter, but they are lower leverage until search mode stops feeling like a long stacked control wall.

## Decision

Choose search-mode decision clarity as the next implementation priority.

This means:
- prioritize extraction earlier in the right rail once the run has meaningful risk on it
- make the relationship between carry, stash, and "leave now vs stay" explicit
- compress destination cards so the right rail behaves more like a departure board and less like a duplicate rules page

## What Stays Deferred

- adding new rooms
- new extraction types
- broader item expansion
- deeper rule variation

Reason:
- the current two-room slice still has more clarity and tension to squeeze out
- adding more content now would dilute learning instead of improving the core loop

## Immediate Follow-Up

1. Keep refining the search decision rail until extraction feels first-class after the first room closes.
2. Return to in-table pressure and opponent tell readability once the search screen is stable.
3. Only then prepare the next system-depth checkpoint.
